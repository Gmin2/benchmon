# web

the benchmon game: react 19, vite, tailwind 4, viem. players log in with email (dynamic), play from an alchemy smart account, and gas is sponsored.

    pnpm install
    pnpm dev

open `http://localhost:5173/home?dev=a` to play without logging in. `?dev=b` in a second tab is the other player, both use a throwaway key kept in this browser. dev players need testnet MON to stake: `cd ../backend && bun --env-file=../.env scripts/fund-dev.ts <smart account> 0.1`.

the backend (`../backend`) should be running too: it reveals locked cards, judges the live duel and opens the betting market for each match.

## layout

- `src/App.tsx` routes: `/` landing, `/home`, `/decks`, `/play`, `/play/:id`, `/watch` (`/trade` redirects), `/ranks`, `/@name` profiles. each screen is lazy loaded
- `src/screens/` the pages. `play/Live.tsx` is the onchain match, `play/Practice.tsx` the free bot match, `play/parts.tsx` what both share
- `src/duel.ts` match actions and polling, `src/market.ts` betting reads, `src/chain.ts` addresses and rpc
- `src/useWallet.ts`, `src/gas.ts`, `src/dynamicClient.ts` login, smart account, sponsored calls
- `src/ui/` the card, kit components, icons, chart
- `src/abi.ts` generated by `../backend/scripts/abis.ts`, `src/ui/generated.ts` and `public/art/` by `../arts/export-web.ts`
- `src/indexer.ts` the graphql client and react-query hooks for the envio indexer: leaderboard, card records, live matches, player records
- `src/mock.ts` practice mode only: the bot opponents and canned duels. `src/mockRoster.ts` is the bundled card list, used for names and art and until the chain stats load


## env

vite reads `../.env` (the repo root) locally, and the process env on vercel.

| name | required | example |
| --- | --- | --- |
| `DYNAMIC_ENV_ID` | yes | dynamic environment id from the dashboard |
| `VITE_ALCHEMY_API_KEY` | yes | alchemy key, rpc and smart accounts |
| `VITE_ALCHEMY_POLICY_ID` | yes | gas manager policy that sponsors moves |
| `VITE_BACKEND_URL` | yes for a build | `https://<app>.azurewebsites.net` |
| `VITE_SITE_URL` | yes for a build, vercel fills it in | `https://benchmon.vercel.app` |
| `VITE_INDEXER_URL` | no | `https://<indexer host>/v1/graphql` |

a production build fails without `VITE_BACKEND_URL`, so it never ships pointing at localhost. `VITE_SITE_URL` goes into the og and twitter tags as an absolute url; on vercel it falls back to the project production domain. without `VITE_INDEXER_URL` ranks, live matches and player records show empty states, and match lists fall back to reading the newest matches from the chain.

## build

    CI=true pnpm install --frozen-lockfile
    pnpm build

`dist/` is a static spa. `pnpm preview` serves it on port 4173.

## deploy on vercel

1. new project from the repo, root directory `web`. `vercel.json` sets the install and build commands, `dist` as output, the spa fallback (every route, `/@name` and `/play/:id` included, goes to `index.html`, files under `/assets` 404 when missing) and the cache headers (hashed `/assets` cached for a year, html no-cache)
2. add the env vars above to the project, plus `ENABLE_EXPERIMENTAL_COREPACK=1` so vercel uses the pnpm version pinned in `package.json`
3. add the vercel domain to the allowed origins in the dynamic dashboard (and the backend cors list), or login fails with a cors error
4. deploy. with a custom domain later, set `VITE_SITE_URL` to it and redeploy so the share tags follow
